Anslutningsresa för deltagarorganisationer inom SDK
Anslutning för deltagarorganisationer
Version: 1.5.2
Denna version gäller från och med 2025-12-01
Informationen nedan beskriver resan för en deltagarorganisation vid anslutning till Säker digital kommunikation (SDK).
1. Inledning
För att ansluta till SDK behöver en ansökan göras hos SDK:s federationsägare (Digg). Detta dokument ger en översiktlig bild över vilka principer Digg arbetar efter, hur anslutningsprocessen går till samt vilka krav som ställs vid anslutning till SDK. Anslutningsresan för deltagarorganisationer ingår i federationsägarens gemensamma regelverk för deltagarorganisationer inom SDK.
Vissa förutsättningar behöver beaktas vid införande av SDK innan anslutningsarbetet påbörjas. Detta dokument beskriver anslutningsresan för en deltagarorganisation. Ytterligare information för deltagarorganisationer finns här: Anslut som deltagarorganisation. Mer information om en deltagarorganisations förberedelser inför införande av SDK finns här: Vägledningar och rekommendationer inför anslutning till SDK.
För att ansluta till SDK behöver deltagarorganisationen först genomgå anslutning till SDK:s kvalitetssäkringsmiljö (SDK-QA), en produktionslik testmiljö där deltagarorganisationen involverar verksamheten för att genomföra grundläggande verksamhetslika tester. Vid ansökan om anslutning till SDK produktionsmiljö utvärderar federationsägaren deltagarorganisationens förmåga att bli godkänd enligt SDK:s regelverk för deltagarorganisationer. Godkännandet är en förutsättning för anslutning till SDK:s produktionsmiljö där deltagarorganisationen kan börja nyttja SDK för utbyte av känslig information.
Detta dokument riktar sig till deltagarorganisationens ansvariga för anslutningsarbetet men även till bl.a. systemtekniker och testare som kommer att utföra anslutningsarbetet och behöver ha en bra översyn över anslutningsprocessen.
2. Vilka aktörer är involverade i anslutning till SDK?
Vid anslutning av deltagarorganisation till SDK är det federationsägaren som bedömer kravuppfyllnad. Denna anslutningsresa fokuserar först och främst på samarbetet mellan federationsägare och deltagarorganisation och leder fram till ett slutligt godkännande till SDK. Processen ger också inblick i de aktiviteter som deltagarorganisationens accesspunktsoperatör och leverantör av meddelandesystem behöver utföra.
Då en deltagarorganisation vill visa följsamhet för en ny meddelandetyp, måste deltagarorganisationen utföra det testprogram och följa de separata kriterier som tagits fram för meddelandetypen.
I detta dokument beskrivs endast hur kravuppfyllnad för meddelandetyperna SDK-meddelande och meddelandekvittens verifieras.
3. Förberedelser inför anslutning till SDK
Anslutning till SDK görs via kontakt med federationsägare i tidigt skede för dialog om anslutningsförfarandet. Inför anslutning till SDK behöver deltagarorganisationen säkerställa att kraven i SDK:s regelverk för deltagarorganisationer inom SDK är uppfyllda. Detta innebär bl.a. att:
Deltagarorganisationen har läst regelverk för deltagarorganisationer inom SDK samt beskrivningar och stödjande dokument.
Deltagarorganisationen har valt en leverantör som är ansluten till OPEN-TEST och har anpassat meddelandesystemet till Diggs regelverk för meddelandesystem. En leverantör kan vara antingen intern inom sin organisation eller en eller flera leverantörer externt. Oavsett ska leverantören ha visat att den uppfyller kraven för meddelandesystem i OPEN-TEST.
Deltagarorganisationen har anskaffat eller anslutit till en godkänd accesspunkt från en av Diggs godkända accesspunktsoperatörer för plattform för eDelivery. Deltagarorganisationen kan också använda en egen godkänd accesspunkt för plattform för eDelivery (se lista på digg.se och Anslutningsresa för accesspunktsoperatörer).
Deltagarorganisationen har anskaffat ett publikt O2O-certifikat för att kryptera och signera meddelanden i meddelandetjänsten. Deltagarorganisationen lägger upp detta certifikat (som innehåller organisationens öppna nyckel) i SDK adressbok.
4. Anslutningsresan - nödvändiga steg för anslutning till SDK QA-miljö
Deltagarorganisationen behöver genomgå tester i SDK QA-miljö för att ha möjlighet att bli godkänd för SDK. Den anslutna organisationen kan både nå och nås från andra deltagarorganisationer inom respektive miljö för SDK.
Anslutningsstegen beskrivs översiktligt nedan. För mer detaljerad information se SDK innehållsspecifikation Meddelande och instruktioner för anslutning till SDK.

6. Avregistrering av deltagarorganisation
Avregistrering av deltagarorganisation kan ske på två sätt:
Deltagarorganisationen väljer att avsluta sin medverkan i SDK. Se nedan vad deltagarorganisationen måste göra för att avregistreras från SDK.
Om deltagarorganisationen inte har följt SDK:s regelverk kan federationsägaren avregistrera deltagarorganisationen enligt regelverk för bristande efterlevnad, se Bilaga för bristande/bristfällig efterlevnad.
När deltagarorganisationen väljer att avsluta sin medverkan i SDK har deltagarorganisationen ansvaret att genomföra följande uppgifter.
Informera federationsägare om avregistrering i SDK.
Avregistrering av metadata i SDK adressbok, SMP och CertPub.
Informera federationsägare om deltagarorganisationen vill vara kvar i SDK QA-miljö. Om ej, behöver deltagarorganisationen avregistrera metadata i SDK adressbok och SMP i SDK QA-miljön.
Efter avslutad avregistrering behöver deltagarorganisationen göra om ovanstående anslutningsresa om den vill bli godkänd till SDK vid en senare tidpunkt.
